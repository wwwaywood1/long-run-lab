# G6 双色球：逐球开奖与长期购买模拟

新增 `/zh/casino/lottery/` 和 `/en/casino/lottery/`。每期机选 1 / 10 / 100 注，按设计稿逐个揭晓六个红球与一个蓝球，标出命中的号码并累计各奖级、花费、返奖、净盈亏与数学期望。可以自动每期购买，或直接模拟坚持买 1 年 / 10 年。二十一点的下一桌链接已可达，赌场大厅加入双色球入口。

基于 G5 完整交付包继续实现，保留此前的英文整句、单复数、高亮、金额格式与共享组件修复。

## 行为和实现

- `Lottery.tsx` / `Lottery.css` 负责状态、计时和显示；规则、号码匹配、奖级、奖金、期望和累计均调用 `engine/lottery.ts`。组件没有概率或赔付计算。
- 复用分段控件、盈亏头、曲线、实物换算、全黑揭晓段与百注方阵。共享 `PnlHeader` 新增可选 `currency`，默认仍是原来的 stake；本页显式使用 `CNY`。
- **英文页面也使用人民币**：`2 yuan` 票价、人民币奖金、人民币盈亏、人民币物价的实物换算。没有将中国真实价格换成美元。动词后的金额不带正负号，独立净盈亏保留符号。
- 动态文案从 `makeCopy()` 读取完整译文，并按 Lottery.json note 的 TEMPLATE 渲染完整英文句子。`1 bet`、`1 draw`、`About 1 week`、`About 1.0 year` 正确使用单数。十注结果补齐 `First prize … yuan`；百注头奖按英文 `7M` / 中文 `700万` 显示，并保留完整人民币无障碍名称。
- 当前开奖完成前锁定注数和购买/批量按钮。停止自动时让当前期完成，不启动下一期；重来和卸载清理计时器。自动等待期间切换注数或批量模拟，会取消旧的下一期回调并使用最新设置。
- 长期购买沿用设计稿算法：未展示的期数按精确奖级概率分类抽样，最后一期生成真实票号并核对同一组开奖号码；每期仍机选新号码。十年曲线按设计稿抽取历史点，保留全段走势并将历史上限控制为 400。
- 静态页保留公益说明、概率时间轴、每注资金流向、真实世界数据和原文语义。高亮按语言分别指定短语；静态句子直接用 JSON 原文，其数字由测试核对。
- 百注格子的大额标签缩小并允许换行，避免 `700万` / `120,000` 溢出；时间轴的秦朝说明错开一行，避免中英文标签重叠。所有交互按钮至少 44px，亏损使用 `var(--loss)`。红球本身的红色是独立球色，不是亏损色。

## 数字来源和待核对事项

1. **官方资金流与固定奖金模拟是两个口径。** 官方比例沿用既有 `OFFICIAL_SPLIT` / `facts.lotto_fund_split`：返奖 51%、公益金 36%、发行费 13%。每注 2 元中，固定三至六等奖的精确期望约 0.49 元，浮动一二等奖与奖池为官方返奖余下的约 0.53 元，公益金 0.72 元，发行费 0.26 元。组件期望则沿用本项目固定头奖 700 万、二等奖 12 万的模型，其返还率约 49.1447%，没有把它强行改成 51%。
2. `presentation_reference` 收录原稿的公益金分配约数、14 亿人口、每人约 450 元、截至 2026 年第 076 期销售额 295.75 亿元，以及时间轴年代。这些是**设计稿引用，不是本轮独立事实核查结果**；原稿仅给出财政部/第一财经（2026-09）、新湖南（2026-07-06）等出处，未附原始链接，仍需 D5 核实。已有 2025 年全国销售额与公益金原始字段保持不变。
3. 保留原稿“普通买家平均回到手里的不到 0.5 元”与“49% 的庄家优势”等说法。前者只统计固定奖，后者采用官方全部返奖口径；不把这两句话混当成同一个期望。没有自行改文案含义。
4. 原稿“花掉的钱 / Spent so far”的实物换算实际上使用净亏损，而不是累计票款；本次按原逻辑保留，累计花费另列在统计行中。
5. 每年 156 期是统一使用的 3 × 52 期假设，不是实时开奖日历；“平均 11,360 年”是按每期 10 注计算的平均等待期，不是保证中奖期限。浮动大奖在模拟中仍按设计稿假设固定，未增加税费、奖金分摊或额外加奖规则。
6. 下一桌刮刮乐仍属于 G7，本轮保留对应的同语言目标路径。
