## D29 检测器页

**怎么验收的**

- 构建通过。`rich()` 自动核对每个带数字的句子和 JSON 一字不差：37.8% / 3.8% / 45.5% / 4.4%、20,000、59%、207、1,069、505。
- 页面正文和设计稿逐行比对，静态部分完全一致。两个黑色段的上下内边距实测和设计稿相同（104px）。
- 390px 宽度下中英文都没有横向溢出。

**Claude 改的 1 处**

- `t(26)`（公式下的说明）：DeepSeek 在交付说明里写“由 GRID 生成”，模板里实际用的却是 `t(26)` 原文，没有接引擎；JSON 里也没有设计稿的下标。现在改为 `rich(26)`，五个备择胜率由引擎的 `GRID` 生成，`L<sub>k</sub>`、`p<sub>k</sub>` 的下标按设计稿补上。

**疑问审定**

1. **初始读数是“—”还是 1.00**：取 1.00。第 0 局时 E₀ = 1 是定义，不是占位符。交互组件服务端渲染的就是第 0 局的真实状态：E = 1.00；在“它什么时候变的？”标签下 R = 0。
2. **“将近 3000 局”还是 2,980**：保留“将近 3000 / nearly 3,000”。“将近”说明这是约数，而且 2,980 确实不到 3,000。新增测试要求模拟中位数落在 [2,800, 3,000) 之间，重算数字后如果越界，测试会报错。
3. **公式只校验了碎片**：可以接受。公式里的阈值 20 和 1000 已经直接用引擎常量。
4. **`footerNote`**：框架已经支持。

## 检测器页的两块交互（Claude）
